# Unpoly migration (in progress)

Current state: Htmxor remains active for unconverted pages. `Unpoly.Blazor` 0.1.0 runs alongside it on .NET 10 static SSR. `Program.cs` registers Unpoly with `HandleAllLinksAndForms = false` so unconverted links/forms keep their current semantics; opt in explicitly when migrating an interaction. `UseUnpoly()` runs before antiforgery and appends `X-Up-Target`, `X-Up-Version`, `X-Up-Mode` and `X-Up-Context` to `Vary`. Keep public caching scoped to the existing allowlist and private pages `no-store`.

`App.razor` renders `<UnpolyHead />` and the existing `<HtmxHeadOutlet />`. Both are temporary: remove Htmxor only after every HX consumer, Razor form handler, TypeScript hook and test has moved. The upstream Unpoly adapter serves static assets from `/_content/Unpoly.Blazor/` and sends ASP.NET antiforgery tokens using `RequestVerificationToken`.

First converted route: `/account/deliveries/{id}/extension-requests`. A direct GET now loads the user's extension requests in the initial SSR response and returns a complete page without JavaScript. A request with `X-Up-Target: #ext-body` also contains that fragment for client-side extraction. No new client controls were added; the pre-existing approve/reject actions still use fetch. This route uses the existing sender-scoped `ListExtensionRequestsQuery`; a foreign or nonexistent id produces the same empty view.

The notification inbox at `/account/notifications/inbox` now renders data on the initial GET. All/unread filters are real links with `up-follow` targeting `#notifications-body` and history enabled. The cursor link loads more on reveal, appending `#notifications-pages` content and replacing its own next-page anchor; without JS it is a visible, followable link. With JS the read-all form is intercepted by `ts/notification-center.ts`, which calls the existing JSON API and reloads the fragment without cache. With JS disabled the same form posts to `/account/notifications/inbox/read-all`: the authenticated endpoint manually validates the antiforgery token, dispatches the same `MarkAllNotificationsReadCommand`, and redirects to the inbox. The original JSON API is unchanged. `DESIGN.md` records the visible load-more control; DAUB tokens and styling remain intact.

Design decision: direct GETs must render usable data without JavaScript, even when this delays first paint. Do not translate HX headers or attributes mechanically: Unpoly expects a full-page response and extracts the target itself. Avoid automatic interception of all links/forms until the remaining HTMX-dependent surfaces and script lifecycles are migrated.
