## Contract applied to every converted route

1. **Direct GET and JavaScript disabled:** render real page/content on first request; accept slower SSR (user decision A). Existing bare fragment routes become complete pages with a layout, or redirect only when direct-entry behavior is intentionally documented and tested. No permanent skeleton. Keep authorization, per-user/tenant scope, and not-found indistinguishability.
2. **Unpoly fragment request:** send a full valid SSR response containing exactly the selectors requested; Unpoly extracts. Do not introduce HX-only fragment endpoints or require `X-Up-Target` for authorization. `UpChrome` may omit chrome but must keep `HeadOutlet` outside; identify any chrome selectors needed in `Provides`. Keep IDs stable across cursor/filter states; assert no duplicate nav/footer in a real browser.
3. **Forms:** use native GET/POST with antiforgery, direct-post/no-JS and validation tests. Htmxor `onpost`/`hxor-eventid` cannot simply become `@formname`/`@onsubmit`: current notification experiment gave `Parameter count mismatch` on GET. Choose a dedicated authenticated HTML/redirect endpoint (or prove native Razor binding in an isolated test) per form. Mutations use existing handlers, never JSON response directly as a fragment; 422 for invalid Unpoly submissions, visible localized failure, no writes during validation requests. Keep JSON API consumers untouched.
4. **Client behavior:** `up-follow`, `up-target`, `up-history`, `up-defer="reveal"`, `up-autosubmit`, `up-poll` are not string-for-string substitutes for `hx-*`. GET handlers must be idempotent (Unpoly may revalidate caches). Cursor links stay usable without JS. JS handlers that update fragments must be authored in `ts/` and survive Unpoly swaps, returning cleanup from `up.compiler` when installed by a compiler.
5. **Cache and security:** no personal SSR content in shared caches. `UseUnpoly()` precedes `UseAntiforgery()`, `Vary` includes `X-Up-Target`, `X-Up-Version`, `X-Up-Mode`, `X-Up-Context` alongside cookie policy; keep public allowlist limited to genuinely safe routes. Test CSRF denial, cross-tenant misses, untrusted targets, status/redirect semantics. Keep DAUB and no-JS download behavior.
