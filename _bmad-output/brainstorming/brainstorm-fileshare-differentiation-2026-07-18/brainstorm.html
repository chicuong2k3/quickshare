Wedge rõ — và 1 rủi ro tồn tại

TeleCloud dùng MTProto làm kho gần-vô-hạn, free. Để thắng, chỉ cần 2 việc đúng; để sống, phải đối diện 1 rủi ro thật.

📦

Chunking phải rock-solid

Đây là wedge. File >2GB → chunk 512MB → upload song song → ghép + verify hash. Làm tốt cái này = "hơn Telegram" thấy được.

⚠️

MTProto userbot = risk ban

ToS Telegram cấm dùng API làm dịch vụ lưu file cho bên thứ 3. Thiết kế ephemeral + obey FLOOD_WAIT + identity-gate + encrypt (blind pipe). Revenue → owned storage.

🛡️

E2E = khiên, không headline

Encrypt-before-chunk giữ nguyên — nhưng vì blob mã hóa Telegram không content-flag được (giảm ban), chứ không phải vì user cần privacy. Key giấu trong link, UX vô hình.

Nền móng

4 việc không thương lượng

📦 Chunking core

512MB/chunk ≤2GB, AES-256-GCM độc lập/AAD anti-swap, manifest encrypt, SHA-256 từng chunk + toàn file, parallel + resume mức chunk, commit-khi-đủ.

🛣️ MTProto gateway

Gateway Python (Telethon/Pyrogram) là nơi duy nhất giữ session. Forum supergroup 1 topic/file → takedown = xóa topic. Obey FLOOD_WAIT, ephemeral mặc định.

🛡️ Encrypt-before-chunk

Defensive blind-pipe: ciphertext không bị content-flag → giảm ban. Key trong URL fragment, vô hình với user. Không marketing "private".

🚪 Sender gating + freemium

Receiver không login. Sender Guest/Verified/Paid. Guest thử 1 file >2GB free (khoảnh khắc convert). Paid = volume/speed → fund owned storage.
