- (decision) Surface: stay on existing .NET Blazor + FastEndpoints web app (WTelegramClient), NOT the brainstorm's Android+Python-gateway sketch. Reuse existing code; chunking/E2E/tiers translate onto current stack.
- (decision) Wedge: headline >2GB single-file auto-chunk ('Telegram without the 2GB ceiling') AND keep share features (expiry/password/branded/paid/file-request) as supporting. Both, not either-or.
- (decision) E2E-before-upload framed DEFENSIVE (ciphertext not content-flaggable => lower Telegram ban risk), NOT marketed as 'private' headline. Key in URL fragment, zero-knowledge by construction.
- (decision) Sender gating asymmetric: receiver never logs in (the wedge vs LocalSend/TG-direct); sender Guest(anon+rate-limit)/Verified(Google OAuth)/Paid. Quota enforced server-side. Guest may send at least one >2GB file free (conversion moment).
- (decision) ToS/ban is existential: obey FLOOD_WAIT, ephemeral default, single Telegram account at MVP, NO account rotation; revenue -> owned storage migration as the real exit.
- (decision) Closed source + freemium. Trust via zero-knowledge-by-construction + network self-check inspector + signed builds (MVP); published crypto spec + verifier next; paid audit/bug bounty later. No oversell badges.
- (event) Brainstorm folder relocated from AndroidAIAgent to TeleCloud/_bmad-output/brainstorming (was misfiled). Source of this PRD.
- (event) Drafted full PRD (Fast path) + addendum from brainstorm sources. PRD: wedge=>2GB chunking + supporting share features; addendum holds chunking schema, MTProto/ToS, quota matrix, trust stack, rejected alternatives.
- (assumption) Guest 100MB single-file cap (quota matrix) conflicts with headline 'Guest sends one >2GB free'; flagged as OQ-3 + addendum D tension, needs a one-shot trial-send bypass.
- (override) PIVOT (party-mode, 6 research missions): backend = OWNED dedicated disk (Hetzner/OVH) + Backblaze overflow, DROP Telegram. Reason: 100u×500GB/mo scenario => Hetzner ~$115/mo vs Telegram ~$210/mo (upload-push = 2x egress) vs R2 $750 vs S3 $7500. Owned is cheapest AND removes ToS ban risk.
- (decision) ToS clarification (verified from source): Bot Platform ToS 5.2(e) bans 'cloud storage sites' but only for Bot API, NOT the MTProto userbot path. API Terms has no explicit file-hosting ban, only 1.4 'no interfering'. Real risk is behavioral (TeleDrive dead, Teldrive self-warns ban) not textual. Still too risky for a paid product.
- (decision) Telegram economic advantage only appears when hoarding (long-retention, disk-exceeding) = exactly the behavior that triggers bans. Send-file product is short-expiry, no hoard => Telegram advantage ~0, risk stays. No economic reason to keep Telegram.
- (decision) Pricing model: sell TRANSFER not RETENTION. Bandwidth cost scales with downloads-per-link, not file size. Survival levers = short expiry + download-count cap + egress passthrough at top tier (MASV model). Flat-fee tiers survive only if avg downloads/link stays low.
- (override) Stripe DEAD in Vietnam (needs US LLC). Payment rails = VietQR/MoMo/ZaloPay. FR-13 paid-download rewritten off Stripe.
- (decision) Wedge shifts from '>2GB dung luong' to WORKFLOW-delivery for studios/editors: E2E=IP-safe (WeTransfer AI-training backlash opened this), branded delivery page, download tracking, longer expiry, local pay. VN localization is table-stakes not moat (Fsend/FPT already there). Unit economics viable (~85% margin); distribution + 'who actually pays' remain UNVERIFIED - must interview 5 real studios.
- (event) Telegram backend code snapshotted to codes/TeleCloud-telegram-archive/ (not deleted from main repo; main still runs on Telegram until owned-storage is built).
- (decision) Ad model: ads ONLY on recipient download page of FREE-sender deliveries. Cleanliness follows the SENDER's Plan: Pro/Studio (paid) => sender clean AND recipient clean (studio pays partly to give clients an ad-free handoff = an upgrade reason). Free consumer => recipient sees ads (interstitial countdown; gambling-but-not-too-dirty acceptable).
- (decision) New accounts get [ASSUMPTION 3-5] clean 'trial' deliveries to feel the pro experience, then fall to ad-supported free if not upgraded. Solves the free-poisons-the-funnel problem: a pro trialing free must not show clients gambling ads.
- (decision) Anti-adblock: use Ad-Shield-style ad-recovery (serve ads via own domain to evade filters, gigafile model) OR soft-wall (ask nicely + retry). NOT hard-block. Reason: hard-block loses the uBlock arms race and false-blocks legit users (Brave/Firefox privacy/DNS filtering) from downloading files they have a right to. gigafile itself does not hard-block.
- (decision) Ad economics: Hetzner bandwidth $0.001/GB; free user capped ~2GB/5-downloads/3-day => ~$0.01 cost; VN CPM $0.10-1 => need 3-30 impressions to break even, x1.7 for adblock. Ads REDUCE free-tier loss, do not make it profitable. Cap egress FIRST, ads second. AdSense unusable (bans file-sharing + E2E = no content control).
