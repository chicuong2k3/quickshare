topic: Payment and plan upgrade flow for QuickShareCloud
updated: 2026-07-26T15:00
---

- (decision) Why: Both revenue capture (paid Pro/Studio subscribers) and infrastructure foundation (plan state for future tier enforcement). Pricing page and Upgrade page exist but /api/upgrade/initiate is a stub.
- (decision) Scope: Ko-fi only. VietQR removed from scope. Post-payment redirects to homepage.
- (decision) Ko-fi flow: Redirect user to Ko-fi product page. Ko-fi webhook confirms payment. Plan lifecycle: Ko-fi manages recurring subscription billing. Webhook extends/ends plan automatically.
- (decision) Cancellation: graceful — user stays on paid plan until billing period ends, then Ko-fi sends an 'expired' event that drops them to free.
- (capability) CAP-1: POST /api/upgrade/initiate — receives plan+billing, returns Ko-fi redirect URL for matching product. Authenticated only.
- (capability) CAP-2: POST /api/payments/kofi/webhook — receives subscription events (created, renewed, cancelled, expired), validates Ko-fi signature, updates User.Plan.
- (capability) CAP-3: Plan lifecycle — plan set to pro/studio on created/renewed webhook. Unchanged on cancellation. Free on expired webhook.
- (capability) CAP-4: Post-payment — Ko-fi redirects user back to QuickShareCloud homepage /.
- (constraint) Ko-fi only for plan upgrades — no VietQR/MoMo/Stripe.
- (constraint) Ko-fi manages recurring billing — QuickShareCloud only reacts to webhook events.
- (constraint) Existing /upgrade?plan=X&billing=Y URL contract must be preserved.
- (constraint) User must be authenticated for /upgrade ([Authorize] already enforced).
- (constraint) User.Plan is a single string field (free/pro/studio) — webhook writes directly.
- (constraint) Ko-fi webhook must validate signature — untrusted requests get 401.
- (constraint) Tech stack unchanged: .NET 10, Blazor SSR, FastEndpoints, EF Core, PostgreSQL.
- (non_goal) No subscription management UI in QuickShareCloud — users manage on Ko-fi.
- (non_goal) No VietQR/MoMo/ZaloPay for plan upgrades.
- (non_goal) No payment history or billing records — Ko-fi handles invoices and receipts.
- (non_goal) No plan downgrade UI. No proration. No team billing.
