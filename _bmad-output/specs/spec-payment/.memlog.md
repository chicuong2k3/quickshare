---
topic: Payment and plan upgrade flow for QuickShareCloud
updated: 2026-07-30
---

- (decision) Why: Both revenue capture (paid Pro/Studio subscribers) and infrastructure foundation (plan state for future tier enforcement). Pricing page and Upgrade page exist but payment integration needed completion.
- (decision) Scope: PayOS only. PayOS is a Vietnamese payment gateway supporting bank transfer (VietQR), card, and e-wallet. Replaced Ko-fi (which had UX issue: message field pre-filled with payment code).
- (decision) PayOS flow: User on `/upgrade` picks a plan → server creates `PaymentIntent` with `PayOSOrderCode` (numeric) → calls PayOS API to create payment link → shows QR code (VietQR) + checkout URL. PayOS webhook confirms payment.
- (decision) Cancellation: graceful — user stays on paid plan until billing period ends, then `SubscriptionExpiryJob` drops them to free.
- (capability) CAP-1: `/upgrade` form POST handler — creates `PaymentIntent` + calls PayOS API to create payment link. Returns `checkoutUrl` + `qrCode`.
- (capability) CAP-2: `POST /api/payments/payos/webhook` — verifies HMAC signature, matches `PaymentIntent` by `PayOSOrderCode`, activates subscription.
- (capability) CAP-3: Plan lifecycle — plan set to pro/studio on payment, unchanged on cancellation, free on expiry.
- (capability) CAP-4: Post-payment redirect — PayOS redirects user to `returnUrl` (`/upgrade`).
- (constraint) PayOS only for plan upgrades — no MoMo/ZaloPay/Stripe.
- (constraint) PayOS handles payment processing. QuickShareCloud reacts to webhook events.
- (constraint) Existing `/upgrade?plan=X&billing=Y` URL contract must be preserved.
- (constraint) User must be authenticated for `/upgrade` (`[Authorize]` already enforced).
- (constraint) `User.Plan` is a single string field (free/pro/studio).
- (constraint) PayOS webhook must pass HMAC signature verification — untrusted requests get 401.
- (constraint) Tech stack: .NET 10, Blazor SSR, FastEndpoints, EF Core, PostgreSQL. PayOS .NET SDK.
- (non_goal) No subscription management UI beyond cancel/change-plan.
- (non_goal) No MoMo/ZaloPay for plan upgrades.
- (non_goal) No proration, refunds, or team billing.
- (event) Implemented: PayOSService (payment link creation), PayOSWebhookEndpoint, Upgrade.razor with PayOS UI.
- (event) All Ko-fi specific code removed. Payment matching now uses numeric `orderCode` (no message field pre-fill issue).
- (companion) payos-products.md — PayOS pricing, webhook config, and entity schema.
- (companion) payment-events-schema.md — payment_events table schema.
