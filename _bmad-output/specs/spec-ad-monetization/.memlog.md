topic: Ad monetization via rewarded video ads for free/Starter tier users
updated: 2026-08-01T20:27
---

- (decision) Why: Freemium model needs monetization for free/Starter tier. AdMob rewarded video ads chosen — highest eCPM (-15 VN) among legally compliant ad types, user opt-in (no forced ads), good UX. Gambling/18+ ads prohibited by Google AdMob policy which auto-filters restricted categories.
- (decision) Ad format: Rewarded video only. Google AdMob via web SDK. User sees reward prompt (Watch ad for +100MB bandwidth), watches 15-30s video ad, receives quota boost on completion. No forced ads, no auto-play. Always show Upgrade to Pro button alongside.
- (decision) Architecture: AdComponent.razor — reusable Blazor SSR component (not a page, a shared component). Lives in Components/Shared/AdComponent.razor. All ad logic (AdMob init, reward callback, quota dispatch) encapsulated in this single component. Pages include it where needed.
- (decision) Plan gating: Only free/Starter plan users see ad components. Pro and Studio users never see any ad. Check User.Plan at render time — if not free, AdComponent renders nothing (empty fragment).
- (decision) Plan gating: Only free/Starter plan users see ad components. Pro/Studio users never see any ad. Check User.Plan at render time.
- (decision) Daily ad limit: Max 3 rewarded ads per user per day. Server tracks via UserUsage daily quota field. Prevents abuse and preserves UX.
- (decision) Quota reward: Each completed rewarded ad grants +100MB daily bandwidth. Server-validated callback only. Resets at midnight.
- (capability) CAP-1: AdMob Rewarded Video integration via AdComponent.razor. Loads AdMob JS SDK, presents reward prompt, plays video on click, calls server callback, updates UI with quota boost.
- (capability) CAP-2: Daily ad count tracking. Server endpoint checks count < 3 before showing prompt, increments on verified completion, resets midnight UTC.
- (capability) CAP-3: Server reward callback POST /api/ads/reward-callback validates AdMob token, increments daily bandwidth +100MB, returns updated quota. Idempotent.
- (capability) CAP-4: Plan-gated rendering. AdComponent renders empty for Pro/Studio. Renders reward prompt skeleton for free users with HTMX lazy-load.
- (constraint) AdMob is the only ad network. Rewarded video only — no banners, interstitials, popups.
- (constraint) AdMob SDK via Google CDN script tag. No npm package.
- (constraint) Server-verified callback only. Client claim insufficient — server validates AdMob reward token before granting quota.
- (constraint) Max 3 ads/user/day. Hard server enforcement. Reward: +100MB per ad.
- (constraint) AdComponent follows HTMX lazy-load pattern (AGENTS.md). Pro/Studio users: zero HTML, zero network requests.
- (constraint) Tech stack: .NET 10 Blazor SSR, Htmxor, EF Core PostgreSQL. JS interop via vanilla modules in wwwroot/js/.
- (non_goal) No banner ads, interstitials, pop-ups, pop-unders, push notifications.
- (non_goal) No affiliate marketing within ad placement.
- (non_goal) No ad-blocker detection or circumvention.
- (non_goal) No ad targeting based on file content, names, or share metadata.
- (non_goal) No gambling, adult, political, alcohol ads — Google AdMob content policies handle filtering.
- (non_goal) No A/B testing of ad formats for initial release.

Defense: Google AdMob SSV mandatory — server independently verifies every reward token with Google before granting quota. No client-side signal trusted.
