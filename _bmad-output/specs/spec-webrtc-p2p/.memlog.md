---
topic: WebRTC P2P transfer as alternative delivery method when receiver is online
updated: 2026-07-20T02:03
---

- (direction) Why: Pain (server bandwidth/storage limits + slow uploads for large files), Opportunity (P2P faster, no size limit when both online), triggered by ZetaShare article showing WebRTC feasibility
- (capability) CAP-1: Browser-to-browser P2P transfer via WebRTC DataChannel when both sender and receiver are online simultaneously
- (capability) CAP-3: No size limit on P2P transfers — files stream directly without server buffering
- (capability) CAP-4: Optional end-to-end encryption with PIN/password that receiver must provide to decrypt/access the transfer
- (capability) CAP-2: Automatic fallback to existing server-based transfer when receiver is offline or P2P connection fails (NAT, firewall)
- (constraint) CONSTRAINT-1: WebRTC DataChannel only — no media (audio/video) streams, pure data transfer
- (constraint) CONSTRAINT-2: Reuse existing WebSocket infrastructure for signaling — no new dependencies for SDP/ICE exchange
- (constraint) CONSTRAINT-3: Chunked streaming with bufferedAmount backpressure — never load entire file into memory
- (constraint) CONSTRAINT-4: P2P must be transparent to end-user — existing UI/UX flow unchanged, user only perceives faster transfer
- (direction) NON-GOAL-1: Server-based transfer remains the primary method — P2P is a transparent optimization
- (direction) NON-GOAL-2: Receiver does not upload files to the system — download-only role
- (direction) NON-GOAL-3: No native mobile apps — browser-only via Blazor Web
- (direction) NON-GOAL-4: No real-time chat or collaboration — file transfer only
- (decision) Pricing decided: Free tier = P2P unlimited + limited server fallback + ads. Paid tiers = P2P unlimited + server quota + features + no ads. P2P must be unlimited in all tiers to compete with LocalSend.
- (assumption) P2P file-size limits would drive users to free alternatives (LocalSend) — P2P must be unlimited across all tiers
- (open_question) Online detection mechanism: WebSocket presence server vs share-link polling? No decision yet.
