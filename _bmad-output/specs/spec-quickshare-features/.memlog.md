- (capability) CAP-1: Upload-to-link (core) — intent: Sender uploads a file (drag/drop, paste, or picker) and receives a share link without signing up. success: File lands on R2 storage via the chunked/multipart path and a share link with an unguessable token is returned; anonymous senders capped at 100 MB, signed-in senders capped by plan; works from mobile and desktop browsers.
- (capability) CAP-2: End-to-end encryption (zero-knowledge) — intent: Every delivery is AES-256-GCM encrypted in the browser; the key rides only in the URL fragment so the server stores pure ciphertext. success: Server and DB never see plaintext or key material; a recipient download in a fresh browser reconstructs a byte-identical file from the fragment key; corrupted ciphertext fails closed.
- (capability) CAP-3: Recipient download without account — intent: Recipient opens the share link on any device and downloads the file without creating an account. success: A fresh browser downloads the file in one click; no login wall; works on mobile and desktop.
- (capability) CAP-4: Download gates (OTP/password/ad) — intent: Sender can protect a delivery with a 6-digit OTP, a password, or both; free-plan recipients may also face a short ad interstitial before download. success: Unverified attempts are blocked; correct OTP/password passes; ad interstitial appears at most once per free-plan delivery and the reward is recorded; gates are sender-controlled per delivery.
- (capability) CAP-5: Expiry and auto-cleanup — intent: Deliveries carry a server-enforced expiry (24 h or 7 d by plan); expired links show a clear expired state and background jobs delete the data. success: An expired link renders an expiration message, never a broken page; cleanup jobs remove expired objects from storage and DB; expiry is enforced server-side, not client-side.
- (capability) CAP-6: Plans and quotas — intent: Free/Pro/Studio tiers cap per-file size, monthly transfer volume, and delivery count; quota state is visible and enforced server-side. success: Over-quota uploads are blocked with a clear message; limits come from a single plan-limits source and are enforced on the server; an upgrade CTA surfaces at the limit.
- (capability) CAP-7: P2P transfer (WebRTC) — intent: Sender and recipient transfer files directly device-to-device via a share code and WebRTC signaling; file bytes never touch the server. success: Two browsers negotiate through the signaling relay, establish a data channel, and transfer the file directly; the server stores no bytes.
- (capability) CAP-8: Payments and subscriptions — intent: Sender upgrades via PayOS (VietQR bank transfer, card, e-wallet); the webhook flips the plan and the subscription lifecycle (renew/cancel/expire) holds. success: Payment intent -> PayOS checkout -> webhook -> plan upgraded; expiry/cancel downgrades the plan; status and receipts visible in billing.
- (capability) CAP-9: Account and profile — intent: Sender signs in with Google (GitHub button present) and manages profile, delivery history, and billing. success: User edits name/avatar, sees past deliveries, and sees billing state; FastEndpoints enforces auth by default with AllowAnonymous only where intended.
- (capability) CAP-10: Download notifications — intent: Sender receives an email when a delivery is downloaded. success: A download event triggers an email to the sender with delivery metadata; unsubscribe is honored.
- (capability) CAP-11: Tools landing pages — intent: Share-text, online-clipboard, and uncompressed-images landing pages drive users into the send flow. success: Each page renders its static shell instantly (HTMX lazy-load) and routes the CTA into the upload/send flow.
- (constraint) HTMX lazy-load is the default for every page with OnInitializedAsync: static shell renders instantly (HX-Request absent -> return immediately), dynamic data fetched via hx-get + hx-trigger=load after load. All internal navigation uses hx-get targeting the content area, never plain anchors. No StreamRendering as primary approach.
- (constraint) Every hx-get/hx-post must carry hx-select for the target element — HTMXor Direct Routing (AddHtmxorComponentEndpoints) is NOT compatible with .NET 10 and is not registered, so partial responses return full HTML documents that must be extracted client-side.
- (constraint) MainLayout must inherit LayoutComponentBase (never HtmxLayoutComponentBase). HtmxorLayout inherits HtmxLayoutComponentBase and renders only @Body for partials via [HtmxLayout(typeof(HtmxorLayout))] in _Imports.razor.
- (constraint) No hx-boost globally. Blazor enhanced navigation handles full-page links; HTMX only for genuine partial server updates (search, forms, real-time data). Static data toggles (pricing monthly/yearly, theme) stay client-side — never HTMX.
- (constraint) Design tokens: --db-* names are an override layer on the DAUB vendor stylesheet — change values, never names (~322 db-* usages depend on them). Foil gold is a fill only, never text color (use --db-color-accent-text). Valley blue = active cell; mountain gray = rest. Radius zeroed; geometry is skewX(-14deg) with glyphs counter-skewed. Font sizes only from DESIGN.md typography.scale closed set.
- (constraint) Download page must work with no JavaScript: the server renders a usable phase and JS only moves on from it. class=hidden must never be on the default phase (DownloadNoScriptTests guard). Browser-only logic (clipboard, sessionStorage, phase switching) is covered by BrowserAppFixture + Playwright.
- (constraint) E2E encryption: AES-256-GCM per-chunk AEAD; key lives only in the URL fragment; AAD binds the manifest. Every upload is encrypted by default — no plaintext toggle. Server is zero-knowledge: it never sees plaintext or key material.
- (constraint) FastEndpoints enforces auth by default. Declare AllowAnonymous() explicitly for public endpoints (delivery download, webhook, payment callback, brand info). Never gate on HttpContext.User.Identity.IsAuthenticated manually; never call AddHtmxorComponentEndpoints.
- (constraint) Never set CreatedAt/UpdatedAt manually — AuditableEntityInterceptor sets both from DateTime.UtcNow. Entities inherit BaseAuditEntity for both; partial entities get metadata-driven support.
- (constraint) Entity-to-DTO mapping via Mapperly (Riok.Mapperly), mappers in Features/<Feature>/Shared/<Entity>Mapper.cs. Exceptions: LINQ .Select() projections with server-side subqueries, and simple value-object responses.
- (constraint) FusionCache for all read-heavy paths (CacheService via DI for Wolverine/endpoints, StaticCache.Instance for Razor inline). TTL bands: download info 30s, file/folder lists 15-30s, user/billing 2-5min, plan limits 1h+, ad tracking 1min. Every mutation handler must invalidate affected cache keys after SaveChangesAsync. Kill switch: FusionCache.Enabled=false.
- (constraint) User-facing strings live in SharedLoc.{en,vi}.resx — never hardcode display copy. JS needs strings via a rendered JSON block (download-i18n pattern), so .js files carry no English literals.
- (constraint) Isolation CSS per component (.razor.css); JS goes in wwwroot/js/ (no .razor.js). Markup returned inside an HTMX partial lacks the component scope attribute, so it must be styled from wwwroot/css/app.css with prefixed global classes (account-, files-, etc.).
- (constraint) Anonymous upload cap is 100 MB (PerkOwnerLimits). One statement per line in C#. string.Empty, never empty-string literal (except where C# mandates compile-time constants). No magic strings/numbers — protocol identifiers, HTTP headers, route paths, config keys, entity statuses, roles live in static class constants (AuthConstants, PlanTierLimits, P2PProtocol, RoutePaths).
- (non_goal) No WebAssembly / InteractiveServer — Blazor Static SSR only (RizzyUI-grade interactivity is not a goal for this product surface).
- (non_goal) No user file library, folder browser, or file/folder management (files/folders CRUD was removed in the QuickShare consolidation). Deliveries are fire-and-forget shares.
- (non_goal) No permanent storage — every delivery expires; nothing is archived server-side indefinitely.
- (non_goal) No file preview, thumbnail generation, or media transcoding on the download page.
- (non_goal) No recipient accounts — recipients never sign up or log in; download is anonymous.
- (non_goal) No copyright enforcement / DMCA compliance system.
