- (direction) User wants a pricing page with multiple subscription tiers, modeled after WeTransfer. TeleCloud currently has no auth, no user accounts, no subscription system.
- (decision) Express mode chosen: input is rich with WeTransfer reference, distill directly. Gaps flagged as open questions.
- (decision) 5 tiers: Free, Starter, Ultimate, Teams, Enterprise. Tier details (prices, features, limits) in companion pricing-tiers.md.
- (decision) Telegram 2 GB per-file limit is a hard ceiling across ALL tiers. Differentiation is via monthly volume, transfer count, expiry duration, and branding features.
- (capability) CAP-1: Display pricing page at /pricing route with monthly/yearly billing toggle, comparing all 5 tiers side-by-side. Success: Page renders all tiers with correct features, prices, and highlight styling. Monthly/Yearly toggle switches displayed prices.
- (capability) CAP-2: Feature comparison table showing which features are available per tier. Success: Each tier visually communicates included vs. unavailable features. Team-gated features show Requires Teams badge on Free/Starter/Ultimate.
- (capability) CAP-3: CTA buttons per tier — Free: Get Started (goes to upload page), paid: Subscribe (triggers checkout). Success: Each tier card has a distinct, functional CTA routing to the correct destination.
- (capability) CAP-4: FAQ section answering common questions (cancel policy, over-limit behavior, payment methods, recipient requirements). Success: Expandable FAQ items with answers matching tier definitions in pricing-tiers.md.
- (constraint) Must use existing tech stack: Blazor Static SSR, RizzyUI components, Tailwind CSS v4, Alpine.js for interactivity (monthly/yearly toggle). No new frontend framework.
- (constraint) Tier definitions, prices, and feature matrices live in pricing-tiers.md companion (single source of truth). Page rendering reads from this canonical data, not hardcoded in components.
- (constraint) Telegram 2 GB per-file limit is hard ceiling for all tiers. No plan offers unlimited file size.
- (non-goal) No payment processing, subscription management, or user authentication. Subscribe button triggers checkout only — actual payment flow is out of scope.
- (non-goal) No backend enforcement of tier limits. The pricing page is informational/marketing. Tier enforcement on upload/download needs auth and subscription tracking first.
- (non-goal) No admin dashboard for managing tiers/prices. Tier data is managed via pricing-tiers.md companion and compiled at build time.
- (assumption) Pricing page is purely static informational content. Tier data compiled at build time from pricing-tiers.md / JSON config. No runtime API calls needed.
- (assumption) Monthly/Yearly toggle with yearly at 20 percent discount vs monthly (standard SaaS convention). Input shows toggle but no specific discount rate.
- (assumption) Team tiers assume user authentication and team management exist. Since TeleCloud has no auth, Teams/Enterprise shown but potentially flagged as coming soon.
- (question) Payment processing is out of scope for pricing page display. Should Subscribe CTA link externally (e.g. Stripe Payment Link) or to an in-app checkout built later?
- (question) User authentication and account system is prerequisite for paid tiers. Build pricing page now as marketing-only, or build auth first then pricing, or together?
