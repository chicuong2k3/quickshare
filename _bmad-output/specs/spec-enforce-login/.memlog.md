topic: Require authentication to use QuickShareCloud
updated: 2026-07-18T18:37
---

- (decision) Why: Pain to solve — anonymous abuse, spam uploads, no per-user rate limits, no ability to track who uploaded what
- (capability) CAP-1: Unauthenticated users are redirected to login — any page not explicitly marked public returns 401 and redirects to /login
- (capability) CAP-2: Login required to upload files — the upload page and its API endpoint require authentication
- (capability) CAP-3: Download links stay public — recipients can download without authentication via /t/{ShareId}
- (capability) CAP-4: Uploads are attributed to authenticated user — temp shares populate OwnerId from the current user
- (capability) CAP-5: API enforces auth server-side — FastEndpoints endpoints require authentication via [Authorize] attribute
- (capability) CAP-6: Per-user rate limits — monthly upload volume and transfer count tracked per user and enforced at upload time
- (capability) CAP-7: Pricing and public pages stay accessible — /pricing and static content remain available without auth
- (constraint) Reuse existing cookie auth + Google OAuth stack — no replacing auth middleware
- (constraint) Download links (/t/{ShareId}) remain public — recipients don't need accounts
- (constraint) Reuse existing PostgreSQL User/UserLogin schema — no new data stores
- (constraint) Rate limits enforce against existing plan tiers (Free/Starter/Ultimate) from pricing page
- (constraint) Copy changes needed on Upload.razor (remove 'no login required') and Download.razor (remove 'No login required')
- (non-goal) No new social login providers — only Google OAuth is active; GitHub/Facebook/TikTok buttons remain placeholders
- (non-goal) No email/password registration flow
- (non-goal) No admin panel for managing users or rate limits
- (non-goal) No WebAuthn, passkeys, or MFA
- (non-goal) No audit log beyond OwnerId on shares
- (direction) Success signal: unauthenticated users redirected to /login; uploads require auth and populate OwnerId; download links stay public; per-user rate limits enforced; copy updated; existing download links continue working
- (event) Self-validate Pass 1 (Coherence): PASS — Rules 1-6 and 8 satisfied. 7 capabilities each with intent+success, no HOW prescriptions, constraints rule things out, 5 explicit non-goals, success signal is concrete and testable, prose is lean.
- (event) Self-validate Pass 2 (Preservation): PASS — All 19 load-bearing claims from input landed in SPEC.md. No wrapper-only content dropped.
