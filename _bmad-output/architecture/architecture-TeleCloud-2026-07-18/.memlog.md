- (decision) AD-1: Paradigm — Continue existing Blazor Static SSR + FastEndpoints + Cookie Auth + Google OAuth. No new auth paradigm.
- (decision) AD-2: Auth enforcement pattern (Server API) — FastEndpoints: remove AllowAnonymous() on protected endpoints (CreateTempShare, Files.Download, all Files/* and Folders/*), add RequireAuthorization(). Only endpoints that stay AllowAnonymous: GET /api/temp/{id} and GET /api/temp/{id}/download.
- (decision) AD-3: Auth enforcement pattern (Web) — Global auth middleware redirect that sends 401→/login for any Blazor page route not in an explicit public allowlist. Allowlist: /login, /pricing, /t/{ShareId}, /antiforgery, /static assets (/css/, /js/, /lib/). Implemented via a middleware or route constraint in Program.cs.
- (decision) AD-4: TempShare OwnerId — Add Guid? OwnerId to TempShare entity, EF migration, populated from CurrentUserService.GetUserIdAsync() in CreateTempShareHandler.
- (decision) AD-5: Rate limit enforcement — New UserUsage entity tracking UserId, billing period start, TotalBytesUploaded, TransferCount for the current billing cycle. Checked before create in CreateTempShareHandler. Quota values per plan tier defined in code (Free: 3GB/10tx, Starter: 300GB/10tx, Ultimate: unlimited).
- (decision) AD-6: Plan tier determination — New UserPlan field on User (string: 'free'/'starter'/'ultimate', default 'free'). User plan is set on first login via OAuth (defaults to 'free') and can be changed when payment integration is built.
- (decision) AD-7: Copy changes — Upload.razor: replace 'anonymous · no login required' with appropriate text. Download.razor: replace 'No login required' with appropriate text. Pricing page FAQ #6 and #2 updated to reflect auth requirement.
- (decision) AD-8: Existing anonymous shares migration — Existing TempShares without OwnerId are left as-is (OwnerId = null). Rate limits don't apply retroactively. The auth gate doesn't break existing download links.
