- (decision) Storage architecture: Configuration-based provider selection via IStorageProvider interface (LocalDisk primary, Backblaze B2 cold overflow). Only one provider active at a time per configuration. Prevents runtime provider confusion and simplifies overflow logic.
- (decision) Chunked upload flow: Parallel chunk uploads to /api/uploads/{uploadId}/chunks/{chunkIndex} with idempotent skip-if-exists logic. Final commit via POST /api/uploads/{uploadId}/commit atomically creates Delivery entity. Allows chunk-level resume and prevents partial delivery corruption.
- (decision) Data model migration: Clean break strategy - new Delivery/Manifest/Chunk entities with EF migration, deprecate legacy File/TempShare tables. One-time migration script transforms existing Telegram-based data. Prevents legacy schema contamination and allows proper chunked storage modeling.
- (decision) Transaction model: Chunks auto-commit individually via Wolverine, only final commit operation runs atomically to create Delivery entity. Balances resume capability (chunks persist across connection loss) with data consistency (Delivery creation all-or-nothing).
- (decision) UploadSession resume architecture: 24-hour TTL with automatic cleanup of expired sessions. Background job runs daily to delete expired UploadSessions and their orphaned chunks. Provides full-day resume window while preventing unbounded storage accumulation.
- (decision) Idempotent chunk uploads: Skip-if-exists logic prevents duplicate storage. Server checks chunk existence by uploadId+chunkIndex before storage; returns existing chunkId if already present. Saves bandwidth on retry and simplifies client-side resume logic.
- (decision) Manifest storage: PostgreSQL co-located with Delivery metadata for fast transactional queries and ACID compliance. Encrypted manifest body stored as bytea column. Avoids separate storage fetch overhead and enables JOIN queries with Delivery metadata.
- (decision) Download abuse protection: Recipient IP tracking with per-IP rate limiting via FR-18. Server logs download metadata (IP, timestamp, shareId) without content access. Enables throttle enforcement and abuse detection while maintaining recipient-no-auth principle.
- (decision) Payment integration: PayOS webhook-based payment verification for paid delivery unlock. Public webhook endpoint receives payment notifications, validates signatures, unlocks Delivery atomically. Real-time payment processing without polling overhead; avoids Stripe unavailability in Vietnam.
- (decision) Overall paradigm: Blazor Static SSR + FastEndpoints + Wolverine vertical slice architecture continues unchanged. Only storage backend replacement (Telegram → owned disk) while preserving existing two-process layout (Web + Server) and Wolverine command bus pattern. Minimizes architectural churn during pivot.
- (decision) Storage service interface: IStorageProvider abstraction with StoreChunk/GetChunk/DeleteChunks operations. LocalDiskStorage as primary provider (Hetzner dedicated disk), BackblazeB2Storage as cold overflow. Configuration-based provider selection prevents runtime provider confusion.
- (decision) Entity relationships: Delivery (1) → Manifest (1) → Chunks (many). UploadSession (1) → Chunks (many). Delivery owned by User (many-to-one). DownloadTracking (many) → Delivery (one-to-many) for IP-based download accounting. All relationships enforce referential integrity via FK constraints.
- (decision) API endpoint structure: /api/uploads/* prefix for chunked upload operations (start, chunk upload, commit). Separate /api/deliveries/* prefix for Delivery CRUD and download operations. Public endpoint /d/{shareId} for recipient downloads (no auth required). Maintains existing FastEndpoints pattern while separating upload session concerns.
- (decision) Error handling and validation: LightResults Result<T> pattern continues for functional error handling. Chunk upload validation (size limits, quota checks) occurs before storage commit. Failed uploads return structured error responses without orphaning chunks. Wolverine transaction rollback prevents partial state corruption on commit failures.
