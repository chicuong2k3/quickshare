# Story 2.1: Add OwnerId to TempShare Entity

Status: review

## Story

As a **developer**,
I want **the TempShare entity to have an `OwnerId` column**,
So that **each share can be attributed to the user who uploaded it**.

## Acceptance Criteria

1. **AC-1 (Entity property):** Given the TempShare entity has been updated, when inspecting the `TempShare` class, then it has a `Guid? OwnerId` property.

2. **AC-2 (Navigation property):** Given the TempShare entity has been updated, when inspecting the `TempShare` class, then it has a `User? Owner` navigation property.

3. **AC-3 (Migration applied):** Given EF migration has been applied, when inspecting the database, then the `temp_shares` table has a nullable `owner_id` column with a foreign key to `users`.

4. **AC-4 (Existing rows unaffected):** Given the migration is applied to a database with existing temp_shares rows, when inspecting existing data, then all existing rows have `owner_id = NULL`.

## Dev Notes

### Entity Pattern

`TempShare` uses `record` with `init` accessors. The new properties must follow the same pattern:

```csharp
// Before
public record TempShare
{
    public Guid Id { get; init; }
    public Guid FileId { get; init; }
    public DateTime ExpiresAt { get; init; }
    public DateTime CreatedAt { get; init; }
    public FileMetadata? File { get; init; }
}

// After
public record TempShare
{
    public Guid Id { get; init; }
    public Guid FileId { get; init; }
    public Guid? OwnerId { get; init; }        // NEW
    public DateTime ExpiresAt { get; init; }
    public DateTime CreatedAt { get; init; }
    public FileMetadata? File { get; init; }
    public User? Owner { get; init; }           // NEW
}
```

### EF Configuration

The `TempShare` entity configuration in `OnModelCreating` needs the foreign key added. `DeleteBehavior.SetNull` means if a user is deleted, their shares remain but `OwnerId` becomes null — safer than Cascade for audit trail.
