# Story 1.1: R2 Infrastructure & IStorageProvider Extension

- **Epic:** Epic 1 — Core Delivery Pipeline
- **Story ID:** 1.1
- **Status:** ready-for-dev

---

## User Story

> As a developer,
> I want R2 storage integrated as the active backend with a clear provider interface,
> So that upload and download flows can use Cloudflare R2 without touching the legacy local-disk backend.

---

## Requirements

### Business Value

This story establishes the storage foundation for the entire R2 delivery pipeline. The current `LocalDiskStorageProvider` proxies every byte through the server, consuming bandwidth linearly with file size. Cloudflare R2 eliminates server egress cost ($0/TB) by having clients interact directly with R2 via presigned URLs. The server becomes a lightweight control plane handling only metadata and signed URLs.

Without this story, no R2 upload or download flow can be built.

### Functional Requirements Covered

- **FR-1:** Split-and-store any-size file — R2 multipart upload foundation
- **FR-3:** Download reassembly with integrity — presigned download URL foundation
- **AR-1:** IStorageProvider extended with R2-specific high-level methods
- **AR-2:** R2StorageProvider registered in DI
- **AR-3:** Object key scheme `uploads/{userId}/{deliveryId}/{fileName}`
- **AR-4:** Delivery.StoragePath populated on commit
- **AR-7:** R2UploadId in UploadSession
- **AR-9:** R2 SSE-S3 limitation accepted (always-on encryption, no SSE headers)
- **AR-11:** Storage reclamation via DeleteObjectsAsync

## Acceptance Criteria

**Given** the application starts
**When** DI container resolves `IStorageProvider`
**Then** the active implementation is `R2StorageProvider`
**And** `LocalDiskStorageProvider` is marked `[Obsolete]` for backward compat

**Given** the project has `IStorageProvider` interface defined
**When** I extend it with R2-specific methods:
- `InitR2MultipartUploadAsync(deliveryId, fileName) -> R2InitResult`
- `GenerateUploadPartUrlsAsync(uploadId, partNumbers) -> R2PartUrl[]`
- `CompleteR2MultipartUploadAsync(uploadId, deliveryId) -> CompletionResult`
- `AbortR2MultipartUploadAsync(uploadId) -> void`
- `GetPresignedDownloadUrlAsync(objectKey, expiry) -> string`
- `DeleteObjectsAsync(prefix) -> void`
**Then** `R2StorageProvider` implements all methods with real R2 S3 API calls
**And** `LocalDiskStorageProvider` throws `NotSupportedException` for new R2 methods

**Given** the R2 config is loaded
**When** `R2StorageProvider` initializes
**Then** it reads `AccountId`, `BucketName`, `AccessKeyId`, `AccessKeySecret` from configuration
**And** validates credentials with a `HeadBucket` call on startup (fail-fast)

**Given** a delivery is created
**When** `Delivery.StoragePath` is set on commit
**Then** the key follows the scheme `uploads/{userId}/{deliveryId}/{fileName}`
**And** the key is generated by `R2ObjectKey.For(userId, deliveryId, fileName)` — never constructed inline
**And** `fileName` is URL-escaped (any `/`, `\`, or control char encoded)

**Given** a delivery expires or is deleted
**When** the background cleanup job runs
**Then** it calls `DeleteObjectsAsync(StoragePath)` to delete all objects with that prefix
**And** confirms deletion via R2 response (not blind delete)

**Given** R2 returns a transient error (5xx, timeout)
**When** a storage operation fails
**Then** `R2StorageProvider` throws `R2StorageException` wrapping `AmazonS3Exception`
**And** the handler returns `502 Bad Gateway` with a structured error body
**And** validation errors (400) are not wrapped as 502

| **AD-1** | `IStorageProvider` extended with R2 methods; `LocalDiskStorageProvider` throws `NotSupportedException` | New R2 methods are high-level use-case boundaries (not leaky S3 abstractions) |
| **AD-3** | DI registers `R2StorageProvider` as `IStorageProvider` | `Program.cs` registers `R2StorageProvider`; `LocalDiskStorageProvider` marked `[Obsolete]` |
| **AD-4** | Object key = `uploads/{userId}/{deliveryId}/{fileName}` | Shared utility `R2ObjectKey.For()` — never inline; fileName URL-escaped |
| **AD-5** | Interface groups multiple R2 API calls behind use-case boundaries | High-level methods: `InitiateUploadAsync`, `CompleteUploadAsync`, `GetDownloadUrlAsync`, `DeleteObjectAsync` |
| **AD-7** | `Delivery.StoragePath` (nullable string) stores R2 object key | Written by commit handler after successful R2 complete — never at start time |
| **AD-8** | Cost-optimal design — no redundant round-trips | `CompleteUploadAsync` calls `CompleteMultipartUploadAsync` directly; single-PUT uses `HeadObjectAsync` |
| **AD-9** | R2 transparent AES-256-GCM at rest, zero config | No SSE headers — always-on; no `x-amz-server-side-encryption` header (R2 rejects it) |
| **AD-10** | R2 UploadId persisted in `UploadSession.R2UploadId` | New column on `UploadSession`; commit handler reads from session, not from client |
| **AD-11** | Fail-fast, no fallback, no silent failures | `R2StorageException` wrapping `AmazonS3Exception`; 502 for R2 failures; 400 for validation errors |

### AWSSDK.S3 R2 Configuration Flags

```
DisablePayloadSigning = true   // R2 doesn't require signed payloads
ForcePathStyle = true           // Required for R2 S3-compatible API
Region = "auto"                 // R2 region identifier
```

These flags are **mandatory** for R2 S3-compatible API. Without them, the SDK will attempt AWS-specific behaviors that fail against R2.

### R2Options Configuration Section

Replaces the current `StorageOptions`. New section:

```json
{
  "R2": {

    "BucketName": "",
    "AccessKeyId": "",

      "UploadPartMinutes": 15,

```

### Consistency Conventions

| Concern | Convention |
|---------|-----------|
| Presigned URL TTL | Upload parts: 15 min. Download: 60 sec. |
| Multipart threshold | 10 MB (configurable via `R2Options.MultipartThreshold`) |
| Object key format | `uploads/{userId}/{deliveryId}/{fileName}` — all lowercase, no trailing slash |
| Upload endpoint naming | `/api/uploads/start-r2` / `/api/uploads/commit-r2` / `/api/uploads/abort-r2` |
| Download endpoint | `GET /api/downloads/{code}` — handler routes based on `Delivery.StoragePath` |

## IStorageProvider Extended Interface

```csharp
public interface IStorageProvider
{
    // Existing (local disk) — kept for backward compat
    Task<string> StoreChunkAsync(Guid chunkId, byte[] data, CancellationToken ct = default);
    Task<byte[]> GetChunkAsync(string storageRef, CancellationToken ct = default);
    Task DeleteChunksAsync(string[] storageRefs, CancellationToken ct = default);

    // NEW: R2 multipart upload
    Task<R2InitResult> InitR2MultipartUploadAsync(
        Guid deliveryId, string fileName, CancellationToken ct = default);
    Task<IReadOnlyList<R2PartUrl>> GenerateUploadPartUrlsAsync(
        string uploadId, IReadOnlyList<int> partNumbers, CancellationToken ct = default);
    Task<CompletionResult> CompleteR2MultipartUploadAsync(
        string uploadId, Guid deliveryId, IReadOnlyList<R2PartEtag> parts, CancellationToken ct = default);
    Task AbortR2MultipartUploadAsync(
        string uploadId, CancellationToken ct = default);

    // NEW: R2 download + cleanup
    Task<Uri> GetPresignedDownloadUrlAsync(
        string objectKey, TimeSpan expiry, CancellationToken ct = default);
    Task DeleteObjectsAsync(
        string prefix, CancellationToken ct = default);
}
```

## R2StorageProvider Implementation Notes

### S3 Client Configuration

```csharp
var config = new AmazonS3Config
{
    ServiceURL = $"https://{accountId}.r2.cloudflarestorage.com",
    DisablePayloadSigning = true,   // R2-specific: no signed payload
    ForcePathStyle = true,          // R2-specific: path-style URLs
    AuthenticationRegion = "auto",  // R2-specific: region = "auto"
};
```

### Key Implementation Details

1. **Multipart flow:** `InitR2MultipartUploadAsync` → `CreateMultipartUploadAsync` → returns UploadId. Part URLs generated by `GetPreSignedURL` with `HttpMethod.PUT` and 15min expiry per part number.

2. **Complete flow:** `CompleteR2MultipartUploadAsync` calls `ListPartsAsync` first to verify, then `CompleteMultipartUploadAsync`. If `ListParts` shows parts missing, return failure without completing.

3. **Small files (<10MB):** `InitR2MultipartUploadAsync` can detect file size below threshold and return a single presigned PUT URL instead of full multipart. The commit handler uses `PutObjectAsync` + `HeadObjectAsync` for verification.

4. **Download URL:** `GetPresignedDownloadUrlAsync` generates a presigned GET URL using `GetPreSignedURL` with `HttpMethod.GET` and the configured TTL (default 60s). Set `response-content-disposition` to `attachment; filename="..."` to force browser download.

5. **Delete by prefix:** `DeleteObjectsAsync(prefix)` uses `ListObjectsV2Async` with the prefix, collects object keys, then calls `DeleteObjectsAsync` (batch delete, max 1000 per call). Iterate if more than 1000 objects.

### Error Handling

```
R2 API failure → R2StorageException (wraps AmazonS3Exception)
                  ├── message: human-readable error context
                  ├── innerException: original AmazonS3Exception
                  └── IsTransient: true for 5xx/timeout, false for 4xx
```

Do NOT implement retry in R2StorageProvider for transient errors — let callers (handlers) decide retry strategy per use case. The single exception is `DeleteObjectsAsync` which may implement internal retry for robust cleanup.
